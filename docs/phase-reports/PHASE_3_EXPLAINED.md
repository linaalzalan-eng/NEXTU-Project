**ما أُنجز فعليًا** (P3-T01 إلى P3-T11):
- بيئة اختبار: Vitest وReact Testing Library، و158 اختبارًا آليًا ناجحًا في 16 ملفًا، ثابتة تحت الضغط (القسم 8).

- حالة المهام: `TasksProvider` مع تحديثات متفائلة (optimistic) وتراجع (rollback) عند الفشل.
- ثمانية مكوّنات جديدة أو مُعاد بناؤها، وصفحة `/tasks` حقيقية بالكامل.

## 3. التقنيات والمكتبات

### Vitest
- **ما هو:** أداة تشغيل اختبارات مبنية على Vite، فتفهم `@/` وJSX دون إعداد إضافي.
- **الأوامر:** `npm run test` (يراقب الملفات ويعيد التشغيل)، و`npm run test:run` (تشغيل واحد للتقارير).
- **المفاهيم:** `describe` يجمع الاختبارات، و`it` اختبار واحد، و`expect(...).toBe(...)` التحقق، و`vi.fn()` دالة وهمية تسجّل استدعاءاتها، و`vi.spyOn` لاستبدال دالة حقيقية مؤقتًا.

### jsdom
متصفح "مزيّف" داخل Node: فيه `document` و`localStorage`، لكن **بلا رسم ولا تخطيط**. لذلك لا يختبر الألوان أو عرض الشاشة. ولهذا السبب أجرينا فحوصًا إضافية في Chrome حقيقي (القسم 7).

### React Testing Library + user-event + jest-dom
- **RTL:** يرسم المكوّن ويبحث عن العناصر **كما يراها المستخدم**: بالدور والاسم (`getByRole('checkbox', { name: 'Read' })`) لا بالـ class.
- **user-event:** يحاكي كتابة ونقرات حقيقية (`await user.type(input, 'Read{Enter}')`).
- **jest-dom:** مطابقات مقروءة مثل `toBeChecked()` و`toHaveFocus()` و`toHaveAccessibleDescription()`.
- لماذا هذا الأسلوب؟ لأن الاختبار الذي يبحث بالدور والاسم يتحقق من الوصولية أيضًا: لو نسينا `label` لفشل الاختبار.

### `localStorage`
تخزين نصّي دائم في المتصفح لكل موقع. نحفظ فيه مصفوفة المهام بـ `JSON.stringify` ونقرؤها بـ `JSON.parse`.

### لا مكتبات جديدة في التطبيق نفسه
كل ما أُضيف `devDependencies` للاختبار فقط (D-26). حجم التطبيق للمستخدم زاد من 306 إلى 329 kB، أي 104 kB بعد gzip.

## 4. شرح الكود

### 4.1 التواريخ كنصوص (`src/lib/dates.js`)

```js
export function addDays(dateString, days) {
  return toDateString(new Date(parseDate(dateString).getTime() + days * MS_PER_DAY))
}
```

- `parseDate('2026-10-14')` ينشئ تاريخًا عند منتصف الليل بتوقيت **UTC**، ثم نجمع أيامًا كاملة ونحوّله إلى نص من جديد.
- لماذا UTC؟ في بعض المناطق (مثل بيروت) تقفز الساعة عند منتصف الليل بسبب التوقيت الصيفي، فيُتخطّى منتصف ليل محلي أو يتكرر. حساب UTC لا يتأثر بذلك، والاختبارات تتحقق منه فعلًا بتشغيلها بتوقيت `Asia/Beirut`.
- `todayLocal()` هي الدالة الوحيدة التي تقرأ ساعة الجهاز المحلية (D-10).
- `startOfWeek` تُرجع السبت (BR-03). ستُستخدم في المرحلة 4.
- **ملاحظة:** النصوص بهذا الشكل تُقارن مباشرة: `'2026-10-13' < '2026-10-14'` صحيحة.

### 4.3 التحقق والاختيار: دوال pure

```js
// src/features/tasks/lib/taskValidation.js
export function validateTitle(title) {
  const value = normalizeTitle(title)
  if (value.length === 0) return 'required'
  if ([...value].length > TITLE_MAX_LENGTH) return 'tooLong'
```

- الدالة تُرجع **رمز خطأ** (`'required'`) لا نصًّا. الواجهة تترجمه: `t('validation.title.required')`. هكذا يبقى المنطق مستقلًا عن اللغة.
- `[...value].length` يعدّ الإيموجي حرفًا واحدًا كما تفعل PostgreSQL، بينما `value.length` يعدّه حرفين.


`today` **يُمرَّر كمعامل** ولا يُقرأ داخل الدالة، فتصبح الاختبارات ثابتة: `selectOverdue(tasks, '2026-10-14')` تُعطي النتيجة نفسها في أي يوم.

### 4.5 الحالة: `TasksProvider` والتحديث المتفائل

هذا أهم مفهوم في المرحلة. مثال الإنجاز:

```jsx
const setTaskCompletion = useCallback(async (task, completed) => {
  replaceTask(task.id, { ...task, status: completed ? 'completed' : 'pending', ... })  // 1. غيّر الشاشة فورًا
  try {
    const saved = await withBusy(task.id, () => tasksService.setTaskCompletion(task.id, completed))  // 2. احفظ
    replaceTask(task.id, saved)                       // 3. خذ النسخة المحفوظة
    return saved
  } catch (caught) {
    if (caught.code === 'NOT_FOUND') removeTask(task.id)
    else replaceTask(task.id, task)                   // 4. فشل؟ أرجع النسخة القديمة
    throw caught                                      // 5. وأبلغ من استدعى
  }
}, [...])
```

- **Optimistic update:** لا ننتظر الخادم لنُظهر النتيجة، فيشعر المستخدم بالسرعة (NFR-02).
- **Rollback:** عند الفشل نعيد **هذه المهمة فقط**، لا القائمة كلها، حتى لا تضيع تغييرات على مهام أخرى (NFR-21).
- **`busyIds`:** أثناء طلب لمهمة ما يكون رقمها في هذه المجموعة، والواجهة تقفل أزرارها. فلا يُرسل طلبان لنفس المهمة معًا، ولا تُرجع نسخة قديمة فوق تغيير أحدث. هذا التحسين جاء من مراجعة الكود.
- **المهمة الجديدة** تأخذ رقمًا مؤقتًا `temp-1` حتى يحفظها الخادم، وتكون أزرارها مقفلة حتى ذلك الحين.
- **التعديل من النافذة** لا يكون متفائلًا: ينتظر الحفظ ويعرض مؤشر تحميل (NFR-02).

### 4.6 `useTaskActions`: الأفعال مع رسائل للمستخدم

```js
function toggle(task, completed) {
  return setTaskCompletion(task, completed).catch((error) => report(error, () => toggle(task, completed)))
}
```

- `report` يعرض Toast خطر فيه زر **"حاول مرة أخرى"** يعيد الفعل نفسه.
- الزر يظهر فقط حين يمكن أن تنجح الإعادة (`NETWORK` أو `UNKNOWN`).
- إن كانت المهمة قد حُذفت في مكان آخر (`NOT_FOUND`) تظهر رسالة هادئة بدلًا منه.
- الفصل هنا مقصود: `TasksProvider` يدير **البيانات**، و`useTaskActions` يدير **ما يراه المستخدم**.

### 4.7 المكوّنات وأهم الـ props

- **`TaskForm({ defaultDate, today, onCreate })`:**
  - عنوان وتاريخ (افتراضيًا اليوم المعروض). Enter يرسل، والحقل يُفرَّغ ويبقى التركيز فيه.
  - الصفحة تمرّر `key={date}` فيُعاد إنشاء النموذج عند تغيير اليوم.
- **`TaskItem({ task, busy, onToggle, onEdit, onDelete, meta, action })`:**
  - مربع اختيار حقيقي `<input type="checkbox">`، واسمه هو عنوان المهمة عبر `<label>`.
  - المسافة تبدّله. المهمة المنجزة يتوسطها خط وعليها علامة ✓، لا لون فقط (US-10).
  - أزرار التعديل والحذف اسمها يتضمن العنوان: `Edit “Read”`.
- **`TaskEditDialog({ task, today, onSave, onClose })`:**
  - مفتوحة ما دام `task` ليس `null`، ومعبّأة بالقيم الحالية.
  - Escape يلغي. تُرسل فقط الحقول التي تغيّرت.
- **`DeleteTaskDialog`:** تحذير BR-07 بأن الحذف نهائي ويؤثر على الإحصاءات السابقة. التركيز يبدأ على "إلغاء"، الخيار الآمن.
- **`DateNavigator({ date, today, onChange })`:**
  - السابق والتالي ومنتقي التاريخ و"اليوم".
  - الأسهم تنعكس في العربية (`mirrorIcon`)، لأن الزمن يتقدّم نحو اليسار.
- **`StatusFilter({ value, onChange })`:** ثلاثة أزرار عليها `aria-pressed`، فيعرف قارئ الشاشة أيّها مفعّل.
- **`OverdueSection({ tasks, busyIds, onToggle, onMoveToToday })`:** المهام المتأخرة مع زر "نقل إلى اليوم"، واسمه الكامل يتضمن العنوان.

4. النموذج يُفرغ الحقل ويُبقي التركيز فيه.
5. `tasksService.createTask` يتحقق مرة ثانية، ويحفظ في `localStorage`، ويُرجع المهمة برقم حقيقي.
6. الـ Provider يستبدل المؤقتة بالحقيقية، فتُفتح أزرارها.
7. إن كان التاريخ غير اليوم المعروض، يظهر Toast "أُضيفت المهمة إلى 16 أكتوبر" **بعد** الحفظ فقط.

### ب) فشل أثناء الإنجاز (اختبار IT-04)
1. النقر على المربع، فيصبح ✓ فورًا (متفائل) ويدخل رقم المهمة في `busyIds`.
2. الخدمة ترمي `ServiceError('NETWORK')`.
3. الـ Provider يعيد المهمة لحالتها، فيرجع المربع فارغًا.
4. `useTaskActions` يعرض Toast: "تعذّر الوصول إلى الخادم..." مع "حاول مرة أخرى".
5. النقر على "حاول مرة أخرى" يعيد الفعل نفسه.

### ج) تغيير تاريخ مهمة
1. "تعديل" يفتح النافذة. `showModal()` في المتصفح يحبس التركيز داخلها.
2. تغيير التاريخ ثم "حفظ": يظهر مؤشر تحميل، وننتظر الخدمة.
3. النجاح يغلق النافذة، والمهمة تختفي من اليوم الحالي، ويظهر Toast "نُقلت المهمة إلى...".
4. التركيز ينتقل إلى عنوان اليوم، لأن زر التعديل لم يعد موجودًا.

### د) المهام المتأخرة
`selectOverdue(tasks, today)` تختار المهام غير المنجزة **قبل** اليوم (اليوم نفسه ليس متأخرًا). "نقل إلى اليوم" يستدعي `updateTask(task, { taskDate: today })`، فتخرج من القسم وتظهر في قائمة اليوم.

## 8. المشاكل والحلول

- **النافذة تعيد تعديلات ملغاة:** فتح نفس المهمة بعد "إلغاء" كان يعرض النص المعدّل القديم. السبب أن الحالة لم تكن تُصفَّر إلا عند تغيّر المهمة. **الحل:** تتبّع الانتقال من مغلقة إلى مفتوحة، مع اختبار يمنع عودة الخطأ.
- **Enter لا يحفظ في نافذة التعديل:** زر "حفظ" كان في التذييل **خارج** `<form>`. **الحل:** خاصية `onSubmit` في `Dialog` تجعل المحتوى والتذييل نموذجًا واحدًا. تحققنا في Chrome أن Enter يحفظ.
- **أرقام عربية-هندية في حقول التاريخ (١٤/١٠/٢٠٢٦):** ظهرت حتى في الواجهة الإنجليزية. شغّلنا Chrome بلغة إنجليزية فظهرت `10/14/2026`. **الخلاصة:** الحقل الأصلي يتبع لغة المتصفح، والصفحة لا تتحكم فيه. سُجّلت محدودية في D-27 بدل بناء منتقٍ مخصص خارج الخطة.
- **العناوين الإنجليزية بعيدة عن المربع في الواجهة العربية:** `dir="auto"` على الكتلة كلها جعل السطر يبدأ من اليسار. **الحل:** `dir="auto"` على `<span>` داخلي، فيحتفظ النص باتجاهه ويبقى السطر بجانب المربع.
- **الفلتر يمتد بعرض الصفحة:** عنصر `inline-flex` داخل عمود `flex` يتمدد. **الحل:** `self-start`.
- **jsdom بلا `<dialog>`:** **الحل:** shim في `setup.js` يحاكي سلوك المتصفح، مع التحقق من السلوك الحقيقي في Chrome.
- **ESLint لا يعرف `process` في الاختبارات:** **الحل:** إعداد خاص لملفات الاختبار فقط.
- **اختبار متقلب (flaky):** فشل اختبار مرة واحدة ثم نجح، ولم تُلتقط رسالته في البداية.

## 10. ماذا تعلمت؟

### المفاهيم الأساسية
1. **Pure functions + `today` كمعامل:** منطق يمكن اختباره بلا React ولا ساعة. `selectOverdue(tasks, '2026-10-14')` تعطي النتيجة نفسها دائمًا.
2. **Service layer كعقد:** الواجهة تعرف `tasksService.createTask()` فقط. تبديل `localStorage` بـ Supabase لا يمس أي مكوّن.
3. **Optimistic update + rollback:** أظهِر النتيجة فورًا، واحفظ في الخلفية، وتراجع عند الفشل، ثم أبلغ المستخدم.
4. **فصل البيانات عن التفاعل:** `TasksProvider` (ماذا حدث للبيانات) و`useTaskActions` (ماذا يرى المستخدم).
5. **Controlled inputs:** قيمة الحقل في `useState`، و`onChange` يحدّثها. لذلك يمكن تفريغ الحقل بـ `setTitle('')`.
6. **اختبار كالمستخدم:** `getByRole('checkbox', { name: 'Read' })` ينجح فقط إن كان المربع مربوطًا بعنوانه، فالاختبار يحمي الوصولية.
7. **Adjusting state on prop change:** نمط React الرسمي لتصفير حالة النافذة عند فتحها (`if (task !== previousTask) {...}`).
8. **التواريخ بلا مناطق زمنية:** "يوم المهمة" نص، والحساب بـ UTC، والعرض بـ `formatDay`.

### أمثلة عملية للتجربة
- في أدوات المطوّر ← Application ← Local Storage، تعديل عنوان مهمة داخل `nextu.tasks` يدويًا ثم إعادة التحميل: يظهر التعديل. هذا يثبت أن الصفحة تقرأ من التخزين فعلًا.
- تشغيل `npm run test` ثم تغيير `TITLE_MAX_LENGTH` إلى 100 في `taskValidation.js`: ستفشل اختبارات UT-02 فورًا وتشرح السبب. بعدها يُعاد الرقم كما كان.
- في `TasksPage.test.jsx` قراءة اختبار "rolls back an optimistic change": يوضّح كيف يحاكي `vi.spyOn(...).mockRejectedValueOnce(...)` انقطاع الشبكة.
