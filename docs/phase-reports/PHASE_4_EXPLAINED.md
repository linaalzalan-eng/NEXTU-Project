## 3. التقنيات والمكتبات

تقنيتان جديدتان في هذه المرحلة، واحدة تلو الأخرى.

### أ) `useMemo` مع الدوال pure (مفهوم React، ليست مكتبة)
- **ما هو؟** `useMemo(fn, [deps])` يحفظ نتيجة حساب، ولا يعيده إلا إذا تغيّر شيء في قائمة الاعتماديات.
- **لماذا نحتاجه؟** التحليلات تمر على كل المهام. بدون `useMemo` ستعاد الحسابات عند كل رسم للصفحة، حتى عند فتح tooltip.
- **المفاهيم:**
  - الدالة pure: نفس المدخلات تعطي دائمًا نفس النتيجة، ولا تقرأ الساعة ولا الشبكة.
  - لهذا يكفي أن تكون الاعتماديات `[tasks, today]`.
- **مثال من المشروع:** `useAnalytics.js` (القسم 4.5).
- **علاقته بـ React:** React يقارن الاعتماديات بعد كل render. إن لم تتغير، يعيد النتيجة المحفوظة.
- **كيف تختبره؟** الدوال نفسها تُختبر بدون React (UT-04 إلى UT-06)، والصفحة تُختبر بالتكامل (IT-02، IT-03).
- **الخلاصة:** القاعدة في `lib/` كدالة pure، والـ hook يستدعيها داخل `useMemo`.

### ب) Recharts 3.10.1
- **ما هي؟** مكتبة رسوم بيانية لـ React. تكتب الرسم كمكوّنات: `<BarChart>`، و`<XAxis>`، و`<Bar>`، وهي تحوّلها إلى SVG.
- **لماذا هي؟** هي المكتبة المعتمدة في الـ stack منذ المرحلة 1، ولا تحتاج كتابة SVG يدويًا.
- **لماذا هذا الإصدار؟** أحدث إصدار مرّ عليه أسبوعان على الأقل، احتياطًا من الإصدارات الجديدة جدًا. ومعه `react-is` 19.3.0 المطابق لإصدار React (peer dependency).
- **المفاهيم الأساسية:**
  - `ResponsiveContainer`: يجعل الرسم بعرض الصندوق الذي يحتويه.
  - `data`: مصفوفة صفوف، وكل `<Bar dataKey="...">` يقرأ حقلًا من كل صف.
  - `stackId`: الأعمدة التي لها نفس `stackId` تُكدّس فوق بعضها.
  - `Cell`: يغيّر لون عمود واحد بعينه.
  - `Tooltip` مع `content`: صندوق يظهر عند مرور الفأرة، ونحن نرسمه بمكوّننا.
- **مثال صغير من المشروع:**
  ```jsx
  <BarChart data={rows}>
    <XAxis dataKey="label" reversed={rtl} />
    <YAxis orientation={rtl ? 'right' : 'left'} />
    <Bar dataKey="currentCompleted" stackId="current" fill="var(--color-pine-600)" />
  </BarChart>
  ```
- **الألوان:** نمرّر متغيرات CSS مثل `var(--color-pine-600)`، فتبقى الرسوم مطابقة لنظام التصميم دائمًا.
- **حجم المكتبة:** Recharts كبيرة، لذلك هي داخل صفحة التحليلات فقط، وهذه الصفحة تُحمّل كسولًا (lazy). الملف الرئيسي لم يكبر تقريبًا (القسم 7).
- **كيف تختبرها؟** jsdom لا يرسم فعلًا، فنختبر الملخص والجدول آليًا، والرسم نفسه في Chrome حقيقي.
- **الخلاصة:** Recharts للرسم فقط. الأرقام تأتي جاهزة من الدوال pure.

### `React.lazy` و`Suspense` (للتذكير)
صفحة التحليلات كانت كسولة منذ المرحلة 2. الجديد أن هذا صار مهمًا فعلًا: كل Recharts (حوالي 112 kB مضغوطة) تُحمّل فقط عند فتح `/analytics` (NFR-03).

## 4. شرح الكود

### 4.1 النسبة الصادقة: `toRate` (`src/lib/stats.js`)
```js
export function toRate(completed, total) {
  if (total === 0) return null            // لا مهام: "—" وليس 0% (BR-06)
  if (completed === 0) return 0
  if (completed === total) return 100
  return Math.min(99, Math.max(1, Math.round((completed / total) * 100)))
}
```
- 199 من 200 = 99.5%، والتقريب العادي يعطي 100%، لكن مهمة ما زالت مفتوحة. لذلك نحصر النتيجة الجزئية بين 1 و99.
- `getDailyStats(tasks, date)` يعدّ مهام اليوم حسب `taskDate` فقط. المهمة التي أُنجزت متأخرة تُحسب ليومها الأصلي (BR-01).

### 4.2 الرسالة: `getMotivationKey` (BR-13)
```js
if (total === 0) return 'motivation.noTasks'
if (completed === 0) return 'motivation.zero'
if (completed === total) return 'motivation.done'
return toRate(completed, total) >= 50 ? 'motivation.close' : 'motivation.started'
```
- "لا شيء منجز" و"الكل منجز" تُقرّر من الأعداد الخام.
- بينهما تتبع الرسالة **النسبة التي يراها المستخدم**: 99 من 200 تظهر 50%، فتأخذ رسالة "تجاوزت المنتصف" (D-28).
- الدالة تعيد **مفتاح ترجمة**، لا نصًا. النص في `ar.js` و`en.js`.

### 4.3 الأسبوع والمقارنة (`weeklyStats.js`)
- `getWeekRange(date)` يعيد السبت والجمعة (BR-03)، ويعتمد على `startOfWeek` من `dates.js`.
- `getWeeklyStats(tasks, weekStart)` يمر على المهام **مرة واحدة**، ويعيد الأسبوع كاملًا مع 7 أيام. نسبة الأسبوع = مجموع المنجز ÷ مجموع المخطط، **وليست متوسط الأيام** (BR-02).
- `compareWeeksToDate(tasks, today)` هو قلب المقارنة العادلة (BR-04):
  ```js
  const from = startOfWeek(today)
  const current = summarize(from, today)                              // السبت → اليوم
  const previous = summarize(addDays(from, -7), addDays(today, -7))    // نفس الأيام قبل أسبوع
  rateDelta: current.rate === null || previous.rate === null ? null : current.rate - previous.rate
  ```
  إذا كانت إحدى النسبتين `null`، يكون الفرق `null`، فتعرض الواجهة "لا توجد بيانات كافية" بدل رقم مضلل.
- `getWeeklyHistory(tasks, today, 8)` يعيد 8 أسابيع كاملة من الأقدم للأحدث، **بما فيها الأسابيع الفارغة**.
- `summarizeHistory(history)` يعيد مجموع المنجز وأقوى أسبوع (التعادل للأحدث، مثل BR-05)، لجملة الملخص تحت رسم الاتجاه.

### 4.4 أفضل أداء (`personalBest.js`)
```js
for (const task of tasks) {
  if (task.status !== 'completed' || task.taskDate > today) continue   // المستقبل لا يُحسب
  byDay.set(task.taskDate, (byDay.get(task.taskDate) ?? 0) + 1)
}
```
- ثم تُجمع الأيام في أسابيع، ويُختار الأعلى. عند التعادل يفوز **الأحدث** (`key > best.key`، والتواريخ نصوص تُقارن مباشرة).
- `isTodayBest` و`isThisWeekBest`: إذا كان اليوم أو الأسبوع هو صاحب الرقم (أو عادله)، تظهر رسالة إيجابية في البطاقة.
- نستخدم **العدد لا النسبة**، لأن 1 من 1 = 100% رقم قياسي سهل ومضلل.

### 4.5 الـ hook: `useAnalytics`
```js
const stats = useMemo(() => {
  const history = getWeeklyHistory(tasks, today, TREND_WEEKS)
  return {
    comparison: compareWeeksToDate(tasks, today),
    currentWeek: history.at(-1),
    previousWeek: history.at(-2),
    history,
    historySummary: summarizeHistory(history),
    best: getPersonalBest(tasks, today),

```
- `tasks` من `useTasks()` (نفس القائمة التي تعدّلها صفحة المهام)، و`today` من `useToday()`.
- الأسبوعان الأخيران من التاريخ هما نفسهما أسبوعا الرسم اليومي، فلا حساب مكرر.

### 4.7 إطار الرسم: `ChartFigure` و`ChartCanvas`
```jsx
<Card title={title} description={description}>
  <figure>
    {legend}
    <div aria-hidden="true">{children}</div>     {/* الرسم نفسه */}
    <figcaption>{summary}</figcaption>          {/* جملة تلخّص الرسم */}
  </figure>
  <details><summary>عرض كجدول</summary>{table}</details>
</Card>
```
- قارئ الشاشة لا يفهم SVG فيه مستطيلات. لذلك الرسم مخفي عنه (`aria-hidden`)، وكل رسم له **جملة ملخّصة ظاهرة** و**جدول حقيقي** فيه نفس الأرقام (NFR-44).
- أطفأنا طبقة لوحة المفاتيح في Recharts (`accessibilityLayer: false`)، لأن عنصرًا مخفيًا يجب ألا يأخذ التركيز.
- `ChartCanvas` هو `<div dir="ltr">` حول الرسم. السبب في القسم 8.

### 4.8 الرسمان
**`DailyChart` — يومًا بيوم (أسبوعان كاملان):**
- لكل يوم عمودان: الأسبوع الماضي (إطار متقطع = "نسختك السابقة") ثم هذا الأسبوع (أخضر صلب).
- كل عمود مكدّس: المنجز في الأسفل، و"مخطط له ولم يُنجز" بلون فاتح فوقه، فيكون طول العمود = كل المخطط.
- اسم اليوم الحالي بخط عريض.

**`TrendChart` — آخر 8 أسابيع:**
- مقياسان مختلفان: العدد (0–28 مثلًا) والنسبة (0–100%). وضعهما على محورين في رسم واحد يوحي بعلاقة غير موجودة.
- لذلك هما **رسمان صغيران** على نفس محور الأسابيع: أعمدة للمنجز، وخط للنسبة.
- الأسبوع الحالي صلب والسابقة متقطعة. الأسبوع بلا مهام: لا عمود، وفجوة في الخط (BR-06).

**الاتجاه (`chartTheme.js`):**
```js
export function directionProps(dir) {
  const rtl = dir === 'rtl'
  return { xAxis: { reversed: rtl }, yAxis: { orientation: rtl ? 'right' : 'left' } }
}
```
في العربية يبدأ الزمن من اليمين: السبت على اليمين، ومحور الأرقام على اليمين، وفي كل زوج يكون عمود الأسبوع الماضي على اليمين لأنه يُقرأ أولًا.

## 5. طريقة عمل المرحلة: تدفق الأحداث

### أ) إنجاز مهمة من لوحة اليوم
1. تضغط على الدائرة بجانب "Run".
2. `TaskItem` يستدعي `onToggle(task, true)` → `useTaskActions().toggle`.
3. `TasksProvider` يغيّر المهمة في القائمة فورًا (optimistic)، ثم يحفظ عبر `tasksService`.
4. `tasks` تغيّرت → `useMemo` في `DashboardPage` يعيد `getDailyStats`.
5. `TodaySummary` يعرض النسبة الجديدة (مثلًا 33% → 67%)، ويتحرك شريط التقدم، ويتغير النص في `MotivationMessage`.

### ب) تعديل مهمة قديمة ينعكس على التحليلات (BR-11)
1. في صفحة المهام تنقل مهمة متأخرة من الأسبوع الماضي إلى اليوم، أو تحذف مهمة منجزة.
2. `TasksProvider` يحدّث القائمة.
3. عند فتح `/analytics`، يحسب `useAnalytics` كل شيء من القائمة الجديدة. لا توجد أرقام مخزنة قديمة (D-09).
4. أرقام الأسبوع الماضي تتغير فورًا. هذا مقصود: الأرقام تطابق دائمًا المهام الظاهرة. اختبار IT-03 يتحقق من ذلك.

### ج) منتصف الليل (BR-10)
1. الصفحة مفتوحة طوال الليل، أو التبويب كان مخفيًا.
2. `useToday` يلاحظ (مؤقت منتصف الليل، أو حدث `visibilitychange`/`focus`) ويعيد التاريخ الجديد.
3. كل `useMemo` يعتمد على `today`، فتتحدث: مهام اليوم، والنسبة، والمتأخرة (مهام الأمس المفتوحة تظهر الآن متأخرة)، وتاريخ الإضافة السريعة. اختبار IT-06 يتحقق من ذلك.

## 8. المشاكل والحلول

## 10. ماذا تعلمت؟

### المفاهيم الأساسية
- **الدالة pure + `useMemo`:** القاعدة تُكتب وتُختبر مرة واحدة بلا React، والصفحة تستدعيها فقط.
- **الصدق في الأرقام:** `null` ليست 0، والنسبة الجزئية لا تصبح 100%، والفرق لا يظهر إذا كان أحد طرفيه بلا بيانات.
- **المقارنة العادلة:** "حتى الآن" مقابل نفس الأيام من الأسبوع الماضي، لا أسبوع ناقص مقابل أسبوع كامل.
- **Recharts:** الرسم مكوّنات، والبيانات مصفوفة صفوف، و`stackId` للتكديس، و`Cell` للون عمود واحد.
- **الرسم المتاح للجميع:** جملة ملخّصة + جدول، والرسم نفسه زينة مفهومة لمن يراه.
- **RTL في SVG:** اتجاه النص يغيّر معنى `text-anchor`. الحل عزل الرسم في LTR وعكسه بالمحاور.
- **كود للتطوير فقط:** `import.meta.env.DEV` + `import()` ديناميكي → يختفي من الإنتاج.

### أمثلة عملية للتجربة
- في `src/lib/stats.js` غيّر السطر الأخير من `toRate` إلى `return Math.round((completed / total) * 100)`، وشغّل `npm run test:run`: سترى اختبار 199/200 في `stats.test.js` يفشل. ثم أرجِعه.
