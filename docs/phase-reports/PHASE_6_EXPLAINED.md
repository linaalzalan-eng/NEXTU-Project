# شرح المرحلة 6 — النسخة الجاهزة للنشر

## 1. النتيجة
وظائف MVP الأساسية مكتملة ومختبرة محليًا. تجهيز النشر جاهز؛ النشر العام ونتائج البريد الخارجي مؤجلة بوضوح، لذلك لا نصف النسخة بأنها Beta منشورة بعد.

## 2. الملفات
`vercel.json` يضبط Vite وnpm ci ومجلد dist وإعادة توجيه مسارات SPA إلى index.html. `docs/DEPLOYMENT.md` يشرح متغيرات البيئة وروابط Auth وفحص ما بعد النشر. README والخطة وسجل التقدم محدثة.

## 3. الأدوات
Vercel لاستضافة نسخة Vite الثابتة. Lighthouse 13.5 استُخدم مؤقتًا خارج تبعيات المشروع لقياس الأداء والوصول. لم نضف مكتبات للتطبيق.

## 4. كيف يعمل التجهيز
Vercel يبني الملفات إلى dist. إعادة التوجيه تجعل فتح /tasks أو /analytics مباشرة يحمّل React Router. متغيرات VITE تقتصر على المصدر ورابط Supabase والمفتاح العام؛ بيانات حسابات الاختبار لا توضع في Vercel.


مثال من `vercel.json`:
```json
"buildCommand": "npm run build",
"outputDirectory": "dist",
"rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
```
الأمر ينشئ dist؛ وعند طلب /tasks من عنوان المتصفح يُحمّل index.html ليختار React Router الصفحة الصحيحة.

## 6. القرارات
D-31: حافظنا على التصميم واللغتين ونطاق MVP، وأجلنا البريد والإعدادات الخارجية والفحوص اليدوية الموسعة. لم نغيّر قاعدة البيانات أو إعدادات الأمان أو نفعّل ميزات مدفوعة.

## 7. النتائج
- النتائج المعتمدة من الجلسة: 363 اختبارًا ناجحًا، Lint وBuild ناجحان، 11 فحص أمان و19 فحص CRUD/RLS بالاتجاهين، واستمرار الجلسة في Chrome.
- الجديد: npm audit بلا ثغرات معروفة، وفحص إعداد Vercel وأنماط الأسرار في الملفات المجهزة وdist ناجح.
- الإحصائيات: بيانات Supabase مؤقتة قورنت بحساب مستقل لعدادات اليوم ونسبته والمقارنة الأسبوعية؛ تطابقت النتائج ثم حُذفت بيانات الفحص.
- 18 حالة تخطيط أساسية ناجحة: ثلاث صفحات × لغتين × 360/768/1280 بكسل. Space من لوحة المفاتيح يغيّر إنجاز مهمة فعلية.
- Lighthouse mobile على نسخة Supabase المحلية:
  - Dashboard: الأداء 99، الوصول 100، LCP=2176 ms.
  - Tasks: الأداء 100، الوصول 100، LCP=1217 ms.
  - Analytics: الأداء 99، الوصول 100، LCP=1208 ms.
- Analytics لا تُحمّل ضمن طلبات Dashboard الأولية. قياس الحسابات على 5000 مهمة موثّق سابقًا ولم يتغير كوده.
الأرقام المحلية ليست ضمانًا لأداء الاستضافة أو كل الشبكات، وLighthouse ليس بديلًا كاملًا لاختبار قارئ الشاشة.

## 8. المشاكل
أداة REST المؤقتة احتاجت توحيد أعمدة صفوف الفحص؛ صُححت الأداة دون تعديل التطبيق. تحذير Leaked Password Protection Disabled قيد معروف ومقبول على Free، وليس ميزة مفعّلة.

## 9. المتبقي

## 10. الفكرة الأساسية
نجاح التطبيق محليًا يثبت جاهزية الكود؛ النشر يحتاج بيئة وروابط صحيحة وفحصًا على النطاق الفعلي. لا نعيد اختبارات ناجحة دون تغيير يبررها، ولا نخلط الاختبار المؤجل بالناجح.

تجربة بعد النشر: افتح /tasks مباشرة ثم حدّث الصفحة. سؤال مراجعة: لماذا يحتاج تطبيق SPA إلى rewrite رغم وجود مسار tasks في React؟ ولماذا لا نضع كلمة مرور حساب الاختبار في Vercel؟
