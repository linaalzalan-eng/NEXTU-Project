# شرح المرحلة 5 — Supabase وAuthentication

## 1. الملخص
أُغلقت المرحلة في 2026-10-22 بطلب صاحب المشروع مع تأجيل اختبارات البريد والإعدادات الخارجية المتبقية (D-31)، دون اعتبار المؤجل ناجحًا.

## 2. الملفات المهمة
- `src/services/supabase/`: Client واحد، خدمات Auth والمهام وترجمة الأخطاء.
- `src/features/auth/`: حالة الحساب، الحراس والنماذج.
- `supabase/migrations/0001_create_tasks.sql`: جدول المهام والقيود والصلاحيات وRLS؛ أكد صاحب المشروع تنفيذه.
- `scripts/security-tests.mjs`: فحوص الأمان بحسابين.

## 3. التقنيات
Supabase يوفّر PostgreSQL وحسابات المستخدمين. React يستدعي طبقة الخدمات بدل الاتصال بقاعدة البيانات من الواجهات. المفتاح العام فقط يدخل Frontend؛ لا مفاتيح سرية.

## 4. كيف يرتبط الكود
`ProtectedRoute` يضع `TasksProvider key={user.id}` داخل جلسة المستخدم، فتُعاد حالة المهام عند تبديل الحساب. الخدمة تحوّل أعمدة قاعدة البيانات إلى عقد JavaScript، وتوحّد الوقت إلى ISO. Dashboard وAnalytics يحسبان من نفس قائمة المهام.

## 5. تدفق الاستخدام
الدخول ينشئ جلسة محفوظة بالمتصفح. الطلبات تحمل الجلسة؛ RLS يسمح فقط بصفوف صاحبها. تأكيد التسجيل يطلب `/dashboard` والاستعادة `/reset-password` على أصل الموقع الحالي. الخروج يزيل الجلسة والمهام من الواجهة.

## 6. القرارات
D-30 يشرح الربط والحراس والاستعادة؛ D-31 يسجّل الإغلاق والتأجيل المعتمد. لم يتغير التصميم أو اللغتان.

## 7. النتائج المثبتة
- 363 اختبارًا ناجحًا في 40 ملفًا؛ Lint وBuild ناجحان بنمط Supabase.
- 11/11 فحص أمان حقيقي ناجح.
- 19/19 فحصًا مباشرًا: دخول الحسابين وCRUD وعزل القراءة والتعديل والحذف بالاتجاهين والخروج؛ حُذفت مهام الفحص.
- 6/6 فحوص Chrome حقيقي: الدخول وتخزين الجلسة واستمرارها بعد تحديث كامل وفتح صفحة محمية، ثم الخروج واستمراره بعد التحديث.
- المراجعة البرمجية النهائية لم تجد مشاكل حرجة أو أمنية.
هذه نتائج الجلسة الموثقة، ولم نكررها عند تعديل المستندات فقط.

## 8. المشاكل والحلول
صُححت بيانات حسابات الاختبار محليًا. عولجت مهلة تحميل Analytics في الاختبار فقط بتخصيص 30 ثانية للـbeforeAll، دون تغيير تأكيداته أو الواجهة.
حسب فحص صاحب المشروع، Security Advisor يعرض تحذيرًا واحدًا: Leaked Password Protection Disabled. الميزة متاحة من Pro فأعلى؛ قيد مقبول على Free، لم نفعّل ميزة مدفوعة. لا يتم فحص الكلمات المسرّبة بهذه الميزة.
المرجع: https://supabase.com/docs/guides/auth/password-security

## 9. المؤجل بوضوح
- البريد الحقيقي: تأكيد التسجيل، استعادة كلمة المرور، رفض القديمة وإعادة استخدام الرابط (ST-10).
- تأكيد Site URL وقائمة Redirect URLs من اللوحة؛ المتوقّع محليًا `http://localhost:5173` مع `/dashboard` و`/reset-password`.
- الفحص اليدوي المتبقي بين المتصفحات. الفحص الآلي للجلسة وRLS ناجح، لكنه لا يثبت تجربة البريد أو متصفحًا ثانيًا.
تُحمل هذه البنود إلى قائمة النشر ولا تُعلَن ناجحة. لا يتطلب التأجيل تغييرًا أمنيًا أو ميزة مدفوعة.

## 10. الفكرة الأساسية
الجلسة تعرف المستخدم؛ RLS يفرض ملكية الصفوف في الخادم. حماية React وحدها لا تكفي. اختلاف المستخدم يعيد إنشاء حالة المهام، والإحصائيات تتبع البيانات نفسها.
